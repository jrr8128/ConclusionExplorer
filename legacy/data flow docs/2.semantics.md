# Game of Logic — Phase 1 Semantic Trace (semantic space)

> Scope: **semantic stage only**. Input: `syntax_space`. Output: `semantic_space` lookup tables used by search.

## 0. What this stage produces (ELI5)

We take every statement from the syntax catalog and translate it into:

* a **list of forbidden boxes** (regions that must be empty), or
* a **list of “at least one of these boxes must have something”** requirements.

Later, the search engine just combines these precomputed bitmasks with fast AND/OR operations.

---

## 1. Glossary

* **region**: one “box” in the Venn-style universe. Each base term is either true or false, so there are `2^term_count` boxes.
* **region_index**: integer `0..region_count-1` naming a region.
* **region_bit**: same idea as region_index; bit position in a mask.
* **region_mask**: fixed-size bitset over regions, stored as `MASK_WORDS` 64-bit words.
* **active_words**: how many of those 64-bit words are actually used this run.
* **requirement_index (rid)**: dense index for a nonempty requirement (used by `semantic_state.req_bits`).

---

## 2. Region encoding

A region is identified by an integer whose binary digits encode which base terms are true.

**Rule:** bit `t` of `region_index` is 1 iff base term `t` is true in that region.

Example (term_count = 3, terms 0,1,2):

* `region_index = 5` → binary `101` → term0=true, term1=false, term2=true.

---

## 3. Data layout (`semantic_space`)

### 3.1 Fixed ceilings (compile-time)

* `MAX_TERMS = 8`
* `MAX_REGIONS = 1 << MAX_TERMS`
* `MASK_WORDS = ceil(MAX_REGIONS / 64)`
* `word_t = uint64_t`

Why fixed-size masks:

* Avoid heap allocations during search.
* Keep memory layout predictable and cache-friendly.

### 3.2 Per-run sizing

* `region_count = 1 << term_count`
* `all_regions`: mask with the lowest `region_count` bits set.
* `active_words = ceil(region_count / 64)`

### 3.3 Term lookup masks

For each base term `t`:

* `regions_where_term_true[t]`: regions where term `t` is true.
* `regions_where_term_false[t]`: regions where term `t` is false.

Literal helpers:

* `true_mask_for(lit)` returns `true[t]` if lit is `t`, else `false[t]` if lit is `¬t`.
* `false_mask_for(lit)` returns the opposite.

### 3.4 Per-statement precomputed effects (aligned by `statement_id`)

All vectors below have length `syn_space.all_statements.size()` and are indexed by `sid.id`.

* `forbidden_regions_by_statement[sid]`:

  * Filled only for **A/E** statements.
  * Meaning: these regions would violate the statement, so they must be empty.

* `required_nonempty_by_statement[sid]`:

  * Filled only for **I/O** statements.
  * Meaning: at least one region in this mask must be nonempty for the statement to hold.

### 3.5 Requirement indexing (for `semantic_state.req_bits`)

* `req_index_by_statement_id[sid]`:

  * `-1` means “no requirement for this statement”.
  * otherwise gives a dense `rid`.

* `req_mask_by_req_index[rid]`:

  * the requirement’s region_mask.

* `req_words = ceil(#requirements / 64)`

---

## 4. Rules

### 4.1 Mask boundary rules

* `region_mask` always has `MASK_WORDS` words, but only the first `active_words` are meaningful this run.
* Bits `>= region_count` must remain 0.
* Any complement operation must be bounded by `all_regions` (never turn on bits for non-existent regions).

### 4.2 Alignment rules

* `forbidden_regions_by_statement.size() == all_statements.size()`
* `required_nonempty_by_statement.size() == all_statements.size()`
* `req_index_by_statement_id.size() == all_statements.size()`

### 4.3 Requirement-index rules

* `req_index_by_statement_id[sid] == -1` iff the statement’s required mask is empty.
* `req_mask_by_req_index` contains only non-empty masks.
* `rid` are assigned densely in increasing `sid` order.

---

## 5. Build pipeline (`build_semantic_space`) — exact step order

1. Assert `term_count <= MAX_TERMS`.
2. Compute `region_count = 1 << term_count`.
3. Build `all_regions = build_all_region_mask(region_count)`.
4. Compute `active_words = ceil(region_count/64)`.
5. `build_term_region_masks`:

   * For each term `t`, scan all regions `0..region_count-1` and set bits where `t` is true.
   * Build false-masks via `all_regions & ~true_mask` (and zero unused high words).
6. `build_forbidden_by_statement` (A/E only):

   * `subject_mask = true_mask_for(subject)`
   * `predicate_mask = (A ? false_mask_for(predicate) : true_mask_for(predicate))`
   * `forbidden = subject_mask & predicate_mask`
7. `build_nonempty_by_statement` (I/O only):

   * `subject_mask = true_mask_for(subject)`
   * `predicate_mask = (I ? true_mask_for(predicate) : false_mask_for(predicate))`
   * `required = subject_mask & predicate_mask`
8. `build_req_index_by_statement_id`:

   * initialize all to `-1`
   * for each statement with non-empty required mask: assign next `rid` and push mask to `req_mask_by_req_index`
   * set `req_words = ceil(#requirements / 64)`

---

## 6. ELI5: what the masks *mean*

* A/E statements are **“these boxes must be empty”** rules.
* I/O statements are **“at least one of these boxes must have something”** rules.

Instead of reasoning about Venn diagrams during search, we precompute which boxes each statement touches. Then search just updates masks.

---

## 7. How this feeds the next stage

This stage makes later operations cheap:

* `apply_premise(pid)` can update state via bit ops using these tables.
* `is_inconsistent(state)` becomes:

  * allowed regions become empty, OR
  * an active requirement has zero overlap with allowed regions.
